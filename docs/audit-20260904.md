### 1.1 三个结构性硬伤

| # | 硬伤 | 为什么阻塞 |
|---|---|---|
| **H-1** | **核心创新点不可判定**（最高优先级） | 最大赌注 = "移除 `unsafe` 块、改用类型级安全标注（`:allowzero` / `*anyopaque` / `extern`）"。但 PRD 未定义：**哪些操作被禁止、在编译器哪一层检查、违反时错误码是什么**。Rust `unsafe` 明确许可 5 类操作，MusLang 删了它却没定义等价的安全不变式 —— "无 `unsafe` 块"作为唯一机制是**不可测试的规范** |

## 3. 终局架构（v9）

### 3.1 设计原则（修正 v8 过度设计）

1. **标准库不是单体** —— "用哪个链哪个"，pay-as-you-go，每个子系统为独立 crate；
2. **三端兼容不现在做** —— 目前仅 1 端（Linux），架构只保证**可扩展**（trait + 分发机制就绪），实装留后续；
3. **runtime 可选** —— `muslang-rt` / `muslang-rt-c` 均可选、可动态链接、可在 L1 中剔除。

### 3.2 互操作：编译期机制，无运行时 FFI 层

- 三种**方言**（MusRust / MusC / MusLang 原生）编译到**同一个 HIR**，共享类型系统 + 借用检查器 + 代码生成器；
- 跨语言调用 = **同一模块内的函数调用**，无 ABI 边界 → 零开销；
- **方言层 = 薄前端**（仅解析 + 类型化 + lowering），所有语义判定在 HIR 上做一次；
- **实现顺序 Rust > C > C++**（Rust 最难：借用/生命周期/Pin，先啃硬骨头；C ABI 简单自然跟着通）。

### 3.3 双 Runtime

| | **muslang-rt** | **muslang-rt-c** |
|---|---|---|
| 布局 | 自有（vtable/胖指针/借用信息） | `repr(C)`，与 C 一一对应 |
| 内存 | `MusAllocator` | `malloc/free`，可桥接 `MusAllocator::from_c` |
| 错误 | 类型化 Result | `errno` / 返回码 / `setjmp` |
| Panic | MusLang unwind | C `longjmp`（**用户态完整语义，v8 内核特化已删除**） |
| 场景 | 纯 MusLang 插件生态 | 既有 C/C++ `.so`、`no_std` 用户态、std 底层 |

**开销结论**：只在**跨这两类 runtime 的边界**产生，同类内部调用 = 0。

### 3.4 三级发布模型

| 档位 | runtime | 用途 |
|---|---|---|
| **L1 core** | 无 | `no_std` 用户态、无动态加载、`<8KB` |
| **L2 hosted** | rt **或** rt-c（二选一） | 宿主进程 + 自有插件 `.so` |
| **L3 compat** | rt + rt-c 并存 | 任意第三方 `.so`，+ABI 描述符（≈ 几 KB） |

### 3.5 标准库：三层 + 按需链接

- **std = 一组独立 crate**，非单一 libstd；`net` 不用 → 链接器整块剔除；
- **sys 层按 `target_os` 分发**：接口在 `std::os` 下定义，**Linux 现在实装，macOS/Windows 留 trait + 空 stub + `compile_error!`**；
- **rt-c = std 的底层 + 互操作的 C 边界**（一身两用），std 本身不产生 FFI 开销（它在 rt-c 侧）。

## 5. 可验证性缺口（量化指标无可验证性）

> 9 项指标都缺"给定值 + 测量协议 + 硬件环境"三要素，是**对标值而非验收合同**（仓库无代码、无可执行基线）。v9 至少需定口径：

| 指标 | v0.3 表述 | v9 建议定稿 |
|---|---|---|

## 7. 里程碑重排

```
M1（6 个月）→ 编译器前端 + 借用检查器(NLL) + C99 后端
            + std 骨架（按需链接机制 + core: fmt/time/...）
            + rt-c(Linux) + L1 / L2
            ⚠️ 裁剪建议：仅保 Rust→C 单向导入；C++/自举/Zig 推 v1.x
            ⚠️ 新增 M1-0（2 周）：语法冻结 + spec/{grammar.ebnf, memory-model.md,
                                    unsafe.md, backend-c99.md, std-sys.md}

v1.x      → std 完整（net/fs/thread/async 运行时）
            + 三端：macOS sys 后端、Windows sys 后端
            + LLVM 后端、自举

v2.0+     → kernel 态 rt-c、cross-language LTO、裸金属 <8KB 极致收紧
```

**M1 裁剪理由**：原 M1 含"链接器集成 + Zig 后端 + 完整互操作 + 自举"，单人 6 个月不可行。**即便 kernel 移出 MVP，裁剪仍独立成立。**

## 10. 限定与风险说明

1. **全篇基于文档审阅**，仓库除文档外零代码（0 star / 0 fork / 0 issue / 0 PR），无法动态验证；所有架构结论为设计建议，需 spike 实测；
2. **"Zig 0.15+ 移除 async/await" 作为 D-2 依据，未独立向 ziglang/zig 官方核实** —— 仅作为设计风险采纳，合并前请自行确认版本号与 `@Frame`/事件循环替代写法；若核实可等价表达，D-2 可降级为"延后至 v1.x"；
3. **"FFI 标准调用零开销"为通用平台知识**，但 MusLang 自有结构跨 runtime 的转换成本需实测；"双堆税"仅在两个 runtime 并存时成立；
4. **ABI 描述符"几 KB"、MLIR 取舍、std 拆分粒度均为估算**，落地前需实测；
5. **`MusAllocator::from_c` 桥接是技术风险项** —— 跨 runtime deallocator 配对需在 M1 spike 验证；
6. **D-3 / D-5（MLIR 是否引入）未决** —— 若接 MLIR，需同步上修 `<8KB`；
7. **"1 端 = Linux"按用户表述处理** —— 若实为 Android/WASM，sys 层起点需换；
8. **三端实装工作量不在架构、在实装**（Rust libstd 为数十人年）—— 建议 MVP 只保证"架构支持三端"，不保证 macOS/Windows 全 API 可用，此条**务必写入 PRD** 避免承诺过度。
