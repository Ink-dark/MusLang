# D-5 是否引入 MLIR — 提议冻结：不引入

| 项 | 内容 |
|---|---|
| 决策编号 | D-5（PRD §3.7.1，状态：待冻结 → 本文件提议冻结） |
| 结论 | **M1~M3 全程不引入 MLIR**；自有 HIR / MIR 管线直连 C99 / LLVM IR / Zig 三后端 |
| 复评触发 | 见 §3（三条量化触发条件，满足其一才重开） |
| 日期 | 2026-09-06 |

---

## 1. 决策

**不引入 MLIR。** 编译器中端保持自有 HIR（单态化，D-13）→ MIR（所有权/借用检查）两层，代码生成直出 C99（MVP）/ LLVM IR（P1，经 inkwell 等绑定）/ Zig（P2，远期复评）。

## 2. 理由（五点，对应 PRD 已定承诺）

1. **`<8KB` 与编译速度指标**（§4.1）：MLIR 运行时 + C++ 依赖使编译器体积、启动开销、编译管线复杂度全面上修——PRD D-5 原文已注明"若引入需同步上修 `<8KB` 指标"，而上修该指标违背 L1 核心承诺；
2. **信创自主链路**（§1.1 / M3-5）：MLIR 属 LLVM 生态（大型 C++ 代码库），引入即让"全工具链纯自主验证（M3-7）"新增一个不受控外部依赖；自举后的 muslangc 也不可能在 M2/M3 内复刻 MLIR 子集；
3. **需求错位**：MLIR 的价值在多级方言基础设施（渐进 lowering、异构加速器、自定义 dialect）。MusLang 的"多前端"需求已由 **D-3 方言层**（薄前端 → 统一 HIR）满足——那是编译期一次 lowering，不是 MLIR 式多级基础设施；三个后端均为"单态化后的具体函数 → 文本 IR"映射，不需要 MLIR 的通用 IR 框架；
4. **版本漂移风险**：LLVM/MLIR 接口逐版本变动（与 D-2 弃 Zig 默认后端的同类理由）；inkwell 式 LLVM IR 直出已隔离该风险，无需再引入一层；
5. **自举负担**（D-16）：M3 完整自举含 C99 后端 MusLang 化——自有两层 IR 的自举工作量可控；MLIR 不可自举（宿主即 Rust 生态绑定）。

## 3. 复评触发条件（量化，满足其一才重开）

| # | 触发 | 说明 |
|---|---|---|
| T-1 | MusCat 生态出现**异构/DSL 编译需求**（GPU / NPU kernel、自定义数据流方言） | MLIR 的 dialect 框架此时才有不可替代性；复评 = 新 PRD 决策 D-5b，且作为**独立工具**（`muslang-dialect`）评估，不进 muslangc 主链 |
| T-2 | P1 LLVM 后端实测：inkwell 直出无法表达所需优化管线（如需要 MLIR pass 级控制） | 先尝试 LLVM IR 直出 + `opt` 管线；确实不足才复评 |
| T-3 | M3 自举完成后引入 **MLIR 作为可选外挂后端**（`--backend=mlir`），主链 `<8KB` 口径**不受影响** | 外挂后端不参与自举、不进 L1 体积口径 |

> **承诺**：复评若引入，按 PRD D-5 原文同步上修受影响指标（仅限外挂路径，L1 core 口径不动摇）。

## 4. 与管线各层的衔接

```
MusLang / Rust / C / C++ 源码
   → 方言薄前端（D-3）
   → HIR（类型 + 单态化，D-13）        ← MLIR 由此层替代？——不替代：HIR 即终局中端
   → MIR（所有权 / 借用 / constant-time 检查，D-12/D-4/D-21）
   → 后端：C99（D-2）| LLVM IR（P1）| Zig（P2）
```
